# 의존성·실행 설정·민감정보 처리 점검

확인일: **2026-11-01 한국 시간**. 실행 중인 9강과 원본 v2.1을 변경하지 않고, v2.1.1 복사본과 기존 설치 환경의 배포판 메타데이터를 읽었습니다. 패키지 설치·업그레이드·삭제는 하지 않았습니다.

## 알려진 의존성 취약점 조회

`requirements.txt`의 직접 의존성 4개에서 출발해 현재 Python 3.15.2·Windows 조건의 기본 의존성을 따라갔습니다. **직접 4개·간접 31개, 합계 35개**의 설치 버전을 조회했습니다. 선택하지 않은 extras와 앱과 관계없는 다른 설치 패키지는 검사 범위에 넣지 않았습니다.

| 직접 의존성 | 설치 버전 | 정확 버전 PyPI 메타데이터 | OSV/PyPI가 반환한 적용 advisory |
| --- | --- | --- | --- |
| Streamlit | 1.66.1 | 확인 | 없음 |
| pandas | 3.1.0 | 확인 | 없음 |
| Requests | 2.34.2 | 확인 | 없음 |
| Pillow | 13.0.0 | 확인 | 없음 |

원자료는 [dependency-audit.json](security/dependency-audit.json)에 있습니다. **OSV 배치 조회 1회와 PyPI 정확 버전 메타데이터 GET 35회**, 합계 36 HTTP 요청이 모두 성공했습니다. 서비스에는 공개 패키지 이름·버전만 보냈고 프로젝트 소스·사용자 자료·인증정보는 보내지 않았습니다. 편의점 API 요청은 0회입니다. 아래의 별도 문서 탐색은 이 36회 집계와 구분합니다.

이미지 방어에서 직접 사용할 예정인 **urllib3 2.8.0도 위 35개에 포함되어 검사됐습니다.** 직접 의존성으로 승격해도 패키지 검사 범위가 새로 늘어나는 것은 아닙니다. 초기 검사 당시에는 Requests의 간접 의존성으로 분류했습니다. 루트가 requirements를 갱신한 후 다시 검사하면 직접 의존성 수는 5개가 됩니다.

이 결과는 **해당 시점에 두 공개 데이터베이스가 설치 버전에 적용되는 알려진 advisory를 반환하지 않았다는 뜻**입니다. 알려지지 않은 취약점·공급망 변조·모든 실행 경로의 무결성을 보증하지 않습니다. PyPI의 정확 버전 존재와 공개 업로드 시각도 확인했으며 미래 버전을 임의로 선택하지 않았습니다. 가장 최근인 검사 대상 배포 파일 업로드는 2026-10-28 UTC였습니다.

## 공식 보안 공지 교차 확인

Streamlit의 [공식 GitHub 보안 공지](https://github.com/streamlit/streamlit/security/advisories/GHSA-7p48-42j8-8846)는 Windows에서 잘못된 경로 처리로 SMB 요청과 NTLM 인증정보 노출이 발생할 수 있는 **CVE-2026-33682 / GHSA-7p48-42j8-8846**를 설명합니다. 영향 버전은 **1.54.0 미만**, 수정 버전은 **1.54.0**입니다. 현재 설치·고정된 **1.66.1은 이 공지의 영향 범위 밖**입니다. 실제 SMB 연결이나 인증정보 추출 시도는 하지 않았습니다.

프로젝트 홈페이지의 [보안 공지 목록](https://streamlit.io/advisories)은 GitHub 최신 공지와 표시 범위가 달랐으므로, 홈페이지 목록만 보고 새 공지가 없다고 판단하지 않았습니다. 정확 버전의 공개 배포는 [PyPI Streamlit 1.66.1](https://pypi.org/project/streamlit/1.66.1/)에서도 확인했습니다.

## 실행 설정과 소스 점검

- Windows 실행 파일은 이미 `--server.address 127.0.0.1`을 지정했습니다. 외부 인터페이스 공개를 의도한 설정이 아닙니다.
- 설치된 Streamlit의 설정을 읽어 CORS 방어·XSRF 방어가 켜져 있고 정적 파일 제공은 꺼져 있음을 확인했습니다. 프로젝트 설정에는 주소가 명시돼 있지 않아 실행 파일을 거치지 않는 직접 실행에서도 로컬 바인딩을 보장하도록 명시하는 보강을 루트에 전달했습니다.
- `.streamlit/secrets.toml`, 임시 작업·캐시·사용자 연결표는 기존 제외 목록에 있습니다. 코드·설정의 GitHub/AWS 개인 키·토큰 형식과 개인 키 PEM 패턴 검사에서 실제 비밀값은 발견하지 못했습니다. 운영체제 자격증명 저장소나 사용자 환경변수의 값을 열람하지 않았습니다.
- 요청 측정 로그는 브랜드·경로·횟수·시간·성공/실패·오류 종류만 기록합니다. 검색어·정확한 좌표·인증정보를 이 측정 로그에 추가하지 않았습니다. 조회 캐시는 사용자별 임시 디렉터리에 있습니다.
- 합성 입력으로 `safe_payload`가 `X-API-Key`처럼 하이픈이 들어간 키, 문자열의 Basic 인증, URL 사용자정보를 충분히 지우지 못하는 것을 확인했습니다. 현재 앱에서 실제 사용자 인증정보가 이 경로로 유출되는 연쇄는 확인하지 못했으므로 **확정 정보유출 취약점으로 계산하지 않았습니다**. 원본 오류 보존 원칙을 유지하는 민감정보 제거 보강 대상으로 루트에 전달했습니다. 실제 비밀값은 사용하지 않았습니다.

## 재검사 방법과 한계

```powershell
python scripts/audit_dependencies.py --inventory-only
python scripts/audit_dependencies.py
```

두 번째 명령만 OSV/PyPI에 네트워크 조회를 합니다. 오류·정확 버전 미확인·요구 버전 불일치가 생기면 `incomplete`로 기록하고 성공으로 처리하지 않습니다. 현재 검사 시점에는 오류 0개·반환 advisory ID 0개였습니다.

`pip-audit`와 `bandit`은 해당 환경에 설치돼 있지 않아 실행하지 않았습니다. 이름·버전으로 수행한 OSV/PyPI 조회를 그 두 도구의 실행 결과로 표현하지 않습니다. 이 점검은 Python 의존성의 공개 advisory와 제한된 소스 패턴·설정 확인이며, Streamlit 프런트엔드의 모든 npm 구성요소, 네이티브 라이브러리의 모든 CVE, 운영체제·브라우저·망 정책까지 검사한 것은 아닙니다. 코드의 공격 경로 및 수정 검증은 루트의 최종 보안 보고와 별도 회귀 검사에 기록합니다.
