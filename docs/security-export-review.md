# CSV 내보내기 보안 점검과 수정

검증일: 2026-11-01, 한국 시간. 원본 `기말 과제 v2.1`의 경로를 확인하고 복사한 `기말 과제 v2.1.1`에서만 수정했습니다. 외부 서버에 공격 요청을 보내거나 스프레드시트 수식을 실제 실행하지 않았습니다.

## 확인한 문제: 외부 이름이 구매 목록 CSV의 수식 셀이 될 수 있음

- 분류: CSV/스프레드시트 수식 주입(CWE-1236).
- 전제: 외부 상품·점포 자료가 악성 문자열을 제공하거나 변조되고, 사용자가 내려받은 CSV를 수식 해석 기능이 있는 스프레드시트에서 열어야 합니다. 인터넷에서 누구나 앱의 데이터를 임의로 바꿀 수 있다고 가정하지 않았습니다.
- 원본 위치: `core/ui/v2_panels.py` 98~105행. 점포 이름과 장바구니 상품 이름을 `rows`에 넣고 103행의 `writer.writerows(rows)`로 가공 없이 저장한 뒤 105행에서 다운로드합니다.
- 데이터 흐름: 외부 응답의 상품·점포 이름 → `StoreProduct` → 장바구니 이름·매장 평가 → 구매안 → CSV 셀. 가격·재고 검증을 통과한 자료에서도 이름을 일반 텍스트로 만드는 처리는 별도로 필요합니다.
- 최소 증거: 원본 구현에서 점포 이름 `=1+1`, 상품 이름 `  =1+1`을 넘기면, 다운로드용 CSV를 표준 CSV 판독기로 읽었을 때 해당 셀에 같은 문자열이 그대로 남았습니다. `csv.writer`의 따옴표 처리는 쉼표·줄바꿈을 한 셀에 담지만 수식 판정을 막는 기능은 아닙니다.

비교 결과 다운로드에는 기존 `core/services/exporting.py` 6~11행의 `_cell`이 있었습니다. 첫 문자만 검사하므로 `\n=1+1`, `  =1+1`에는 적용되지 않았고, 작은따옴표에만 의존했습니다. 이 경로도 같은 공통 처리를 사용하도록 보강했습니다. 앱의 표 네 곳은 입력 프레임을 그대로 전달해 표 도구 모음의 CSV 다운로드에서도 외부 문자열이 보존되었습니다.

이 증거는 위험 문자열이 다운로드 셀까지 도달한다는 재현입니다. Excel·LibreOffice에서 실제 수식 실행이나 외부 자료 유출을 시도한 결과가 아닙니다. CSV 자체가 앱 서버에서 코드를 실행한다는 의미도 아닙니다.

## 적용한 처리

`core/security/csv_cells.py`의 `csv_cell`과 `csv_safe_frame`을 사용합니다.

1. 수식으로 오해될 수 있는 문자열 앞에 보이는 고정 접두어 **`[텍스트] `**를 붙입니다. 작은따옴표가 사라지는 앱별 동작에 기대지 않고 셀의 시작을 일반 텍스트로 만듭니다.
2. `=`, `+`, `-`, `@`뿐 아니라 선행 공백·제어문자·보이지 않는 형식 문자·스프레드시트의 텍스트 표시용 작은따옴표 뒤의 기호를 검사합니다. 전각 `＝`, `＋`, `－`, `＠`도 검사합니다.
3. CSV 작성기는 계속 표준 라이브러리를 사용해 쉼표·따옴표·줄바꿈이 다른 셀이나 행으로 빠져나가지 않게 합니다.
4. 숫자형 수량·가격·음수 값과 정상 한국어 상품명·`1+1`·바코드는 그대로 유지합니다. 계산용 원본 모델이나 저장된 상품 연결 정보는 바꾸지 않습니다.
5. 비교 CSV와 구매 목록 CSV에 적용합니다. 표 도구 모음은 셀 변환 콜백이 없으므로 안전하게 만든 프레임 복제본을 표에 전달합니다. 위험 이름은 화면에서도 `[텍스트] `가 붙어 보입니다.

프레임 적용 위치는 `streamlit_app.py`의 매장 비교표·조회 기록표와 `core/ui/evidence.py`의 재고 응답표·브랜드 상태표입니다. 원본 프레임은 수정하지 않습니다. 모든 스프레드시트와 사용자의 수동 편집·접두어 제거 이후까지 안전하다고 보장하지 않습니다.

## 검증

신규 `tests/test_security_csv_exports.py`는 10개 검사를 포함합니다.

- 수정 전 두 다운로드 경로의 최소 재현 2개가 실패했고 수정 후 통과했습니다.
- 공백·탭·개행·NUL·보이지 않는 문자·전각 기호·작은따옴표 앞자리 변형을 방어합니다.
- 한국어 상품명·행사 표기·식별 코드·수량·금액·음수 숫자의 값과 형식을 보존합니다.
- 쉼표·따옴표·개행이 포함된 위험 문자열을 내보낸 뒤 다시 CSV로 읽어도 셀 수와 행 수가 늘지 않습니다.
- 프레임의 위험 셀·열·인덱스가 처리되고 원본 프레임과 숫자 열은 바뀌지 않습니다.
- 실제 재고 응답표·브랜드 상태표 호출에서 내장 다운로드에 전달되는 프레임 복제본도 검사합니다.
- 모의 LIVE 원본 모델의 이름 `=1+1`을 실제 상품 연결·매장 평가·근거 검증·구매안 생성에 통과시킨 뒤 실제 UI 다운로드 인수를 검사합니다. 정상 계산은 유지하면서 CSV의 점포·상품 셀에 접두어가 붙습니다. 이 검사는 외부 API 성공을 가장하지 않습니다.

신규 10개와 기존 비교 내보내기·구매안·v2 화면 검사를 포함해 **관련 33개 검사 통과(8.393초)**, 수정 파일 컴파일 검사도 통과했습니다. 실행 명령은 `python -m unittest tests.test_security_csv_exports tests.test_exporting tests.test_split_purchase tests.test_v2_app -q`입니다. 전체 프로젝트 검사 수는 상위 보안 검증 문서의 최종 실행 결과를 기준으로 합니다.

## 근거

[OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection)은 수식 시작 문자·제어문자·전각 변형과 CSV 따옴표만으로 충분하지 않은 이유를 설명합니다. 현재 문서는 Excel의 저장 후 재열기에서 작은따옴표 기반 처리가 사라질 수 있고 스프레드시트 전반에 보편적으로 안전한 한 가지 형식은 없다는 한계도 명시합니다. 이 앱은 사람이 읽는 다운로드에 명확한 일반 텍스트 접두어를 사용하고 원본 계산 자료를 보존하는 방식으로 처리합니다.
