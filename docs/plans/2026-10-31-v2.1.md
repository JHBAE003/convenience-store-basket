# v2.1 구현 계획과 확인 기준

원본 v2는 수정하지 않는다. 필요한 추적 파일 98개를 새 폴더로 복사했고 .git·가상환경·로그·캐시·인증정보는 가져오지 않았다. 원본 SHA256 목록은 `docs/v2-source-manifest.json`에 저장했다. 업로드와 배포는 하지 않는다.

## 구현 순서

1. 기존 실행·134개 검사 기준을 확인한다.
2. 최신 공개 문서와 MCP 도구 스키마를 확인하고 주 조회와 필요한 보조 조회로 정리한다.
3. 상품·매장·재고 캐시와 진행 중 요청 공유, 제한된 재시도, 조건별 오류·측정 기록을 구현한다.
4. 상품 후보와 선택 상품의 재고 조회를 구분한다. 공통 바코드와 브랜드 코드를 혼동하지 않고 사용자 확인 연결을 재사용한다.
5. 행사 기간과 알려진 조건을 구조화하고 한국 날짜 기준으로 계산 가능 여부를 판정한다.
6. 기존 사진 검색·장바구니·비교·구매 도우미를 유지하면서 정보 상태와 확인 시각을 읽기 쉽게 다듬는다.
7. 새 동작별 검사와 전체 검사를 실행하고 로컬 브라우저에서 상품 검색·시연 비교·작은 화면을 확인한다.

## 코드 점검에서 확인한 차이

- config의 기본 재고 캐시는 1,800초지만 화면의 세션 관리자가 300초로 덮어썼다.
- 재고 두 경로는 동일 중계 서비스를 공유하며 항상 동시에 실행됐다. 독립 출처 검증으로 설명할 수 없다.
- 재고 응답 완료 시각이 원본 자료 시각으로 사용되는 경로가 있었다.
- 공식 GS25 주소는 새 사이트로 이동한다. 기존 HTML 파서가 그대로 작동한다고 가정하지 않는다.

## 완료 기준

- 정상 0/빈 결과, 오류, 누락, 수량 미확인을 구분한다.
- 다른 사용자·상품·위치·조건의 결과와 오류가 섞이지 않는다.
- 앱의 강제 재조회는 앱 캐시만 우회한다고 설명한다.
- 과거 자료의 원본 시각을 새로 만들지 않는다.
- 만료·조건 미확인 행사와 불확실한 연결을 확정 가격에 사용하지 않는다.
- 실시간 장애를 시연 자료로 바꾸지 않는다.
- 자동 검사와 실제 외부 점검 결과를 분리해 기록한다. 실행 시간 개선은 같은 조건으로 측정한 경우에만 수치로 주장한다.

## 완료

2026-10-31: 구현·전체 자동 검사 211개·실행 파일 기동·브라우저 확인·원본 98개 보존 대조 완료. 외부 원격 장애와 GS25 공식 수집의 미확인 범위는 README 및 검증 기록에 명시했다.
