## 계산량 측정

로컬 단일 실행: 가상 점포12곳·상품6종·각12개·방문최대3·모든 판매행 2+1인 인공 입력에서 298개 매장 조합, 전체 구매 후보298개, 최소금액4,800원, **14.888초**. 기본 시연보다 큰 상한 시험이며 평균/벤치마크 비교나 성능 보장이 아니다. 브라우저에서 이 상한 입력을 직접 편집해 실행한 것은 아니다. UI 기본 시연은 4점포·3상품이다. 상한 규모에서는 대기 시간이 발생할 수 있다.

## 별도 검토와 수정

읽기 전용 코드 검토에서 엄격 예산만 부족할 때 일부 구매 예시가 누락되는 P2를 발견했다. 예산 내 추가 1개 비용 기반 참고 예시를 보강하고, 재고와 예산이 동시에 부족할 때 예산 진단을 추가했다. 참고 예시의 최대 확보/최소금액 최적해는 보장하지 않는다는 문구를 UI·README에 넣었다. 수정 후 별도 재검토는 문제 해결로 판정했고 관련 엔진17개 검사를 통과했다. 그 뒤 최종 엔진·화면20개를 다시 실행했다.

## 남은 제한

- 정상 전체 수량 구매안은 지원 범위 내 정확 계산. 예산 부족의 일부 구매 참고 예시는 탐욕법이며 최적해 보장 대상이 아님.
- 거리·지도는 직선/개략 배치. 실제 도보 경로·교통비·소요시간 미제공.
- UI 시연은 고정 상품3종·점포4곳이며 엔진 상한은6종·12곳. 임의의 품목/점포 절삭은 하지 않음.
- 기존 LIVE 코드는 보존·오프라인 회귀만 확인. 외부 서비스의 현재 정상 동작, 신규 인증, 수집 복구는 미검증.
- 새 가상환경 설치, 다른 OS/브라우저, 휴대폰·200%확대·스크린리더 검증은 미실행.
- 브라우저 자체 통신의 전체 네트워크 로그를 계측하지 않았음. TEST Python 경로 외부 연결 0은 socket 차단 검사로 검증했으며 원격 지도/이미지 자원을 코드에 넣지 않음.
- 외부 배포·GitHub 업로드·유료 API/LLM 사용 없음.
