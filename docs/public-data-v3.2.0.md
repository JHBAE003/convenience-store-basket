# v3.2.0 공공자료 연동

2026-11-10 공개 페이지에 포함된 Swagger와 코레일 OAS를 확인하여 구현했습니다. 이번 작업에서 공공 API의 인증키를 발급하거나 데이터 조회 요청을 보내지는 않았습니다. 기존 LIVE 수집기와 LIVE 전환·모의 공급자 검사는 실행하지 않았습니다.

### 확정 구매안과 구분

- 기존 LIVE 공급자와 TEST 공급자, 추천 엔진은 변경하지 않았습니다. 새 공공자료는 LIVE 화면의 접힌 참고 조회 영역에서 사용자가 버튼을 눌렀을 때만 요청합니다.
- 조사 가격이 있더라도 점포별 현재 판매가·정확한 재고가 확인되지 않으면 기존 구매 추천에 채워 넣지 않습니다. 재고 조회 실패를 공공자료나 가상 재고로 대체하지 않습니다.
- 참가격은 [공식 소개](https://price.go.kr/tprice/portal/pricenewsandtpriceintro/tpriceintro/getPriceIntro.do)에서 격주 조사를 안내합니다. API 메타데이터의 ‘실시간’ 표기는 실시간 POS 가격을 뜻하지 않습니다. 명세의 조사일 설명은 금요일이므로 화면 기본값은 직전 금요일이며, 그 날짜에 반드시 자료가 있다고 보장하지 않습니다. 날짜를 자동으로 바꿔 반복 요청하지 않습니다.
- 참가격 상품 ID는 바코드가 아니며 판매점 ID도 기존 MCP 점포 코드와 다릅니다. 조사 상품은 사용자가 상품명·규격을 확인해 선택합니다. 본사 자료를 인근 가맹점 값으로 자동 연결하지 않습니다.
- 할인 종료일을 지났으면 ‘종료’로 표시합니다. 날짜가 없으면 ‘기간 미확인’입니다. 1+1 표시가 있더라도 2+1, 회원·카드·교차증정 조건을 추정하지 않습니다. 참고 행사는 모두 추천 계산에서 제외합니다.
- 코레일 자료는 가격·재고 필드가 없는 상품 사전입니다. 상업 설명의 재고 활용 문구를 실제 재고 데이터로 해석하지 않습니다. 상품명이나 규격 유사도로 바코드를 자동 연결하지 않습니다. 사용자가 확인한 참고 바코드 연결만 현재 세션에 저장하며 원래 상품 코드·연결표·재고 요청은 바꾸지 않습니다. 모드 변경/세션 종료 후에는 보존하지 않습니다.
- 영양정보는 후보 목록입니다. 같은 상품·제조사·기준량을 검증하지 않은 채 장바구니 영양 합계나 건강 추천에 사용하지 않습니다. 성분 미제공을 0으로 바꾸지 않습니다.

## 요청 계약·상한

- 참가격: `https://apis.data.go.kr/B551919/ProductPriceInfoService`
  - `/getProductInfoSvc.do`, `/getStoreInfoSvc.do`: `ServiceKey`.
  - `/getProductPriceInfoSvc`: `serviceKey`, `goodInspectDay`, `goodId`로 선택 상품만 조회합니다. 기간 검색/전 상품 가격 반복 요청은 하지 않습니다.
  - XML/JSON 및 `iros.openapi.service.vo.*` 래퍼 모두 읽고, 상품·업체 코드와 원본 필드는 인증값을 제거한 `Result.payload`에 보존합니다.
- 상가정보: `https://apis.data.go.kr/B553077/api/open/sdsc2`
  - `/smallUpjongList`의 키 이름은 `servicekey`, `/storeListInRadius`는 `ServiceKey`입니다.
  - 반경 최대 2,000m. 편의점 업종 코드 조회 1회(캐시) 후 최대 3페이지 × 500행을 조회합니다. 받은 범위에서 선택 브랜드를 분류하고 중복 행을 제거합니다. 상호·지점명 분류이므로 공식 브랜드 식별을 보장하지 않습니다.
- 코레일 [공개 OAS](https://infuser.odcloud.kr/oas/docs?namespace=15168114/v1):
  - `https://api.odcloud.kr/api/15168114/v1/uddi:948a104f-44a9-4591-9d02-ca6dcce16c7a`
  - 명세에 상품명/바코드 서버 검색 변수가 없어 이를 임의로 만들지 않았습니다. 한 번에 최대 3페이지 × 1,000행, 기본 1페이지입니다. 시작 페이지를 사용자가 바꿀 수 있습니다. 받은 페이지에서만 검색하며 결과가 없어도 전체 상품 미존재로 확정하지 않습니다.
- 영양정보: `https://apis.data.go.kr/1471000/FoodNtrCpntDbInfo03/getFoodNtrCpntDbInq03`
  - `FOOD_NM_KR`, `pageNo`, `numOfRows=100`, `type=json`, `serviceKey`.
  - 100행 초과 시 일부 결과 표시. 임의 바코드 검색이나 품목 이름 자동 연결을 하지 않습니다.

## 키·캐시·시간·오류

키는 `.streamlit/secrets.toml` 또는 환경변수에서 읽습니다. 기본 키를 같이 사용해도 네 API 각각의 활용신청/승인은 필요합니다. `PUBLIC_DATA_SERVICE_KEY` 또는 `PUBLIC_PRICE_KEY`, `PUBLIC_STORES_KEY`, `PUBLIC_CATALOGUE_KEY`, `PUBLIC_NUTRITION_KEY`로 개별 설정할 수 있습니다. 키는 TEST에서 읽지 않습니다.

세션별 클라이언트·최대 64개 결과 캐시를 사용합니다. 기본 TTL은 조사 가격/상품/판매점 6시간, 매장 24시간, 코레일 상품 24시간, 영양 7일입니다. 예제 설정 파일에서 조정할 수 있습니다. 모드 전환 시 기존 초기화 흐름이 세션 자료와 키 클라이언트를 비웁니다.

같은 세션의 동일한 진행 중 요청은 Future로 공유합니다. API·전체 조건을 캐시 키로 쓰며 다른 세션의 자료·오류와 공유하지 않습니다. 키 설정이 바뀌면 해당 세션 클라이언트를 교체합니다. 캐시를 읽어도 최초 수신 시각을 새 시각으로 바꾸지 않습니다. 페이지별 수신 시각과 캐시 여부도 각각 보존합니다. 자료 자체의 시각이 없으면 ‘미제공’이며 앱 수신 시각으로 대체하지 않습니다.

강제 재조회는 정상 결과의 앱 캐시만 우회합니다. 진행 중 요청 공유와 실패 30초 대기는 계속 적용됩니다. 고정 HTTPS 주소만 호출하고 리디렉션은 따르지 않습니다. 429/5xx·연결 오류는 1회만 재시도하며 응답당 3MB를 상한으로 둡니다. 서비스별 요청 간격을 최소 0.3초 두고, 실패 후 30초 대기합니다. 원본 오류 코드는 `Result.error_code`로 보존하고 키/요청 URL을 화면 오류에 그대로 출력하지 않습니다. 원본 응답에서 인증값을 제거하고, 세션 메모리에 최근 요청 100개의 출처·시간·성공 여부만 기록합니다.

정상 빈 응답·원본 미제공·해석 실패·인증 실패를 구분합니다. 일부 페이지 실패 시 받은 자료와 누락을 표시합니다. 0원·가격 미확인을 현재 판매가로 취급하지 않습니다.

## 확인 범위와 남은 한계

- 인증키와 각 서비스 승인 여부는 설정하지 않은 상태입니다. 따라서 실제 가격 응답·매장 포함 범위·바코드 상품 커버리지·기관 서버 가용성을 검증했다고 주장하지 않습니다.
- HTTP 전송부와 LIVE 공공자료 화면은 사용자 지시를 유지해 실행 검증하지 않았습니다. 공개 문서 기반으로 구현했으며 인증키 설정 후 별도 확인이 필요합니다.
- 새 검사는 저장된 예시의 순수 파싱·날짜/바코드·신뢰도 표시만 검사합니다. 기존 61개 TEST 전용 회귀 검사는 그대로 실행합니다. TEST 공급자·SQLite·추천 엔진·지도·그림·기존 테스트 코드는 동일 파일을 유지합니다.
- 실제 요청 수·속도 개선율은 미측정입니다. 상한과 캐시는 구현값이며 실제 운영 성능 수치가 아닙니다.
- 식약처 구형 유통바코드 API는 2018년 이후 최신화 중단, 과거 생필품 할인 파일은 2020년 기준이어서 주 수집원에 넣지 않았습니다.
