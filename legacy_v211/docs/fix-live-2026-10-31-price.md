# v2.1 가격·사진 상품 연결 보완

## 확인한 원인

1. 재고와 공식 행사 목록이 서로 다른 상품 식별자 공간을 사용합니다. 행사 수집기는 이미지 파일 번호·상품 카드 번호를 `product_code`에 보존하고, 재고 응답은 해당 서비스의 내부 코드를 제공합니다. 이 값이 다를 때 엄격한 동일 상품 매칭은 거절합니다.
2. 코드가 없으면 기존 `same_product`는 제조사·용량까지 확인해야 합니다. 공식 목록의 전체 이름이 같아도 용량이 생략된 상품은 연결되지 않아, 참고로 보여줄 수 있는 가격까지 전달되지 않았습니다.
3. 정확한 상품 코드를 연결해도 공개 목록에 1+1·2+1이 동시에 있거나 조건이 미확인이면 행사 선택 함수가 실패하고 **가격도 함께 버렸습니다**. 결제 가능한 행사를 확정하지 못하는 것과 공개 목록의 가격을 표시하지 못하는 것은 서로 다릅니다.
4. 사진 카탈로그는 공식 이미지 파일 번호를 바코드와 내부 코드 필드에 함께 보관했으나, 그 식별자의 출처가 장바구니 연결로 전달되지 않았습니다.

## 적용한 변경

- `same_product`, 바코드/GTIN 판정, 장바구니 상품 연결의 엄격한 기준은 유지합니다.
- `same_catalog_reference`를 별도로 추가했습니다. 동일 브랜드·전체 상품 지문 일치·명시 규격 충돌 없음·공통 바코드 충돌 없음인 공개 목록만 **참고 가격 전용**으로 연결합니다. 이미지/상품 카드 번호의 출처를 명시한 자료에 한해 재고 내부 코드와의 값 차이를 참고 목록 조회에서 구분합니다.
- 이 약한 참고 연결은 상품 코드, 재고, 행사, 이미지 자동 재사용을 변경하지 않습니다. `REFERENCE` 가격과 출처만 전달하며 확정 결제액이 되지 않습니다.
- 행사 조건을 선택할 수 없어도 동일 상품의 유일한 가격은 참고 가격으로 보존합니다. 서로 다른 가격이 있으면 최저가를 임의로 고르지 않습니다.
- 현재 매장에서 확인한 가격은 목록 가격으로 덮어쓰지 않습니다. 상품·점포별 기존 원본 정보도 유지합니다.
- `raw_payload.reference_price_candidates`에 후보 가격·상품명·식별자·출처·확인 시각을 보존합니다. `reference_price_match`는 `identifier` 또는 `exact_name_reference_only`입니다. UI는 확정 판매가와 참고 가격을 구분해 이 값을 사용할 수 있습니다.
- 사진 카탈로그와 공식/제3자 목록 수집기에 `raw_payload.identifier_source`를 추가했습니다. `catalog_link_for`는 선택 필드 `CatalogLink.identifier_source`가 있을 때 이를 기존 연결표와 함께 저장합니다. 기존 CSV는 기본 빈 값으로 계속 읽습니다.

## 공개 출처 확인 범위

실제 재고 서비스 요청은 수행하지 않았습니다. 다른 작업 담당자의 브랜드별 제한된 점검과 중복하지 않았습니다.

CU 공개 행사 화면 GET 2회로 폼과 스크립트만 확인했습니다. `plusAjax.do`는 실제 행사 `listForm`을 직렬화합니다. `searchKeyword` 등은 공통 메뉴 스크립트의 다른 상품 페이지 이동 코드에만 있었고 실제 행사 폼 입력으로 확인되지 않았습니다. 따라서 행사 검색에 임의의 키워드 매개변수를 추가하지 않았습니다. 실제 행사 POST 요청도 하지 않았습니다. 두 GET의 메서드·상태·공개 코드 근거는 `docs/research/fix-price-cu-search-contract.json`, `fix-price-cu-form-contract.json`에 기록했습니다. 인증 값·쿠키·헤더는 수집하지 않았습니다.

CU·세븐일레븐의 전체 행사 목록 최초 수집은 지연될 수 있으므로 일반 재고 비교에서는 새 수집을 시작하지 않도록 분리했습니다. 검증되지 않은 서버 키워드 검색 기능이 있다고 가정하지 않습니다. 이미 확인한 상품 목록의 참고 가격과 재고를 먼저 표시하고, 사용자가 행사 추가 확인을 선택했을 때만 제한된 목록을 수집합니다.

## 검사

`tests/test_live_price_recovery.py` 신규 8개 검사:

- 서로 다른 식별자 공간에서도 같은 전체 표기의 공개 목록 가격만 REFERENCE로 보존.
- 다른 용량·맛·포장·제조사·브랜드는 참고 가격도 잘못 연결하지 않음.
- 출처 표시 없는 상충 내부 코드와 상충 바코드는 이름으로 덮지 않음.
- 같은 식별자의 미검증 중복 행사에서도 가격을 보존하되 행사 할인 계산은 하지 않음.
- 상충 가격은 후보로 모두 보존하고 임의 최저가를 고르지 않음.
- 현재 점포 가격과 행사는 덮어쓰지 않음.
- 사진 목록의 참고가와 식별자 출처를 유지.

신규 검사와 기존 행사·사진·매칭·근거 검사 60개를 함께 실행해 통과했습니다. 모의 응답을 사용한 결과이며 외부 점포의 현재 가격이 검증됐다는 뜻은 아닙니다.


## 재고 조회를 막던 전체 행사 수집 분리

기존 `PromotionManager.search`는 CU의 2개 행사 탭에서 최대 30페이지씩, 세븐일레븐의 4개 탭에서 최대 10페이지씩 수집한 다음 재고 결과를 반환하는 호출 흐름에 있었습니다. 네트워크가 느린 경우 가격 수집 때문에 이미 받은 재고 화면까지 오래 기다리게 됩니다.

API:

```python
promotion = PromotionManager(cache_path=path, defer_catalog=True)
# 일반 재고 비교: 유효 캐시만 사용하고 없거나 만료됐으면 UNKNOWN으로 즉시 반환
promotion.search('CU', '콜라')
# 사용자가 행사 추가 확인을 선택했을 때만 목록 수집
promotion.search('CU', '콜라', allow_catalog_fetch=True)
```

- `defer_catalog=False` 기본값은 기존 독립 호출자의 호환성을 유지합니다.
- `defer_catalog=True`의 내장 CU 수집기는 `max_pages=2`, 세븐일레븐은 `max_pages=1`로 생성합니다. CU는 2개 탭×2페이지, 세븐일레븐은 4개 탭×1페이지로 **브랜드별 명시적 추가 확인 1회당 최대 4 HTTP POST**입니다.
- 수집기 자체의 기본값은 기존 CU 30·세븐일레븐 10페이지입니다. 외부 호출자는 생성자 `max_pages`로 상한을 명시할 수 있습니다.
- 일반 조회는 유효 행사 캐시를 재사용합니다. 캐시가 없거나 만료됐으면 네트워크 요청 없이 빈 목록과 `UNKNOWN: 행사 목록은 추가 확인 버튼으로 조회할 수 있습니다.`를 반환합니다. 이를 행사 없음으로 확정하지 않습니다.
- 다른 요청에서 명시적 수집이 진행 중이어도 일반 재고 조회는 완료를 기다리지 않습니다.
- 페이지 상한에 도달하면 전체 반환 범위를 부분 확인으로 표시합니다. 캐시 재사용·동일 수집 공유·검색 결과 없음에서도 `PARTIAL` 표시를 유지합니다.
- GS25·이마트24의 기존 키워드별 조회는 변경하지 않았습니다.

`tests/test_deferred_promotion_catalog.py`의 신규 11개로 재고 경로의 행사 HTTP 0회, 유효/만료 캐시, 명시적 조회, 부분 범위 보존, 동시 요청 중 비차단, 레거시 호환, 두 브랜드의 각 4 POST 상한을 검증했습니다. 신규 검사와 기존 행사·가격 복구·상품 매칭 검사 총 64개가 통과했습니다. 요청 수 상한은 모의 응답 검사 결과이며, 실제 외부 지연시간 개선율을 측정한 것은 아닙니다.


## 펩시 수동 연결에서의 표기 차이

이번 실제 조회에서 GS25 `롯데)펩시콜라600MLPET`, CU `롯데)펩시콜라P600ml`, 세븐일레븐 `칠성)펩시콜라600ml`, 이마트24 `롯데)펩시콜라펫600ml` 표기가 관측됐습니다. 같은 상품을 사용자가 확인해 연결하는 화면에서도 `롯데`와 `칠성`이라는 표기 차이를 제조사 충돌로 처리해 연결이 막혔습니다.

- 용량 파서는 명시된 PET·PACK·CAN·BOTTLE 포장 접미어를 받아 `600MLPET`도 600ml로 읽습니다. 임의의 영문 단어를 단위 뒤에 허용하지 않습니다. PACK2/2PACK 같은 명시적 묶음 수 역시 비교합니다.
- `conflicting_mapping_variants(left, right)`는 **사용자 직접 확인 전용**입니다. 펩시 음료에서 관측된 롯데·칠성·롯데칠성·롯데칠성음료 표기를 비교용 복제에서만 정리합니다. 다른 제품에 롯데=칠성 규칙을 일반화하지 않습니다.
- 원본 상품명·제조사·규격 메타데이터는 바꾸지 않습니다. 자동 매칭의 `same_product`와 `conflicting_variants`는 제조사 표기 차이를 계속 거절합니다.
- 수동 확인에서도 500ml/600ml, 제로/일반, 라임/망고 등 알려진 맛, 묶음 수의 차이는 차단합니다.

공식 근거는 [롯데칠성음료의 펩시 소개](https://company.lottechilsung.co.kr/kor/company/tasteworld/view.do?detailsKey=29) 검색 결과의 펩시 및 `#펩시 #음료 #롯데칠성음료` 표시와 [2022 지속가능경영보고서](https://company.lottechilsung.co.kr/common/file/sustainability_2022_01_KOR.pdf)의 펩시콜라·펩시제로 브랜드 표기입니다. **공식 제조사 관계와 실제 조회의 약칭을 근거로 한 제한된 수동 확인 설계**이며 공식 API의 제조사 별칭 사전이라고 주장하지 않습니다. 이 담당자의 독립 웹 열기는 502, Python 원문 요청 1회는 로컬 인증서 검증 오류로 실패했습니다. 인증서 검증을 끄지 않았고, 원문 재확인 성공으로 기록하지 않습니다.

`tests/test_manual_pepsi_mapping.py` 신규 8개와 기존 매칭·참고가격·사진 검사 총 47개가 통과했습니다. 자동 매칭의 엄격한 제조사 정책 유지, 원본 불변, 실제 네 표기의 용량 파싱, 다른 용량·맛·포장 거절을 포함합니다.
