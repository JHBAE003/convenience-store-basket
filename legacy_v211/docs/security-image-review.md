# 상품 사진 다운로드 보안 점검

확인일: 2026-11-01, 한국 시간. 검사 대상은 v2.1 원본, 수정 대상은 v2.1.1입니다. 원본 파일·9강 앱·실제 편의점 서버는 변경하지 않았습니다.

## 확인한 입력 경로

외부 재고/상품 응답의 이미지 URL은 `live_mcp_adapter.py`의 `_product_image`에서 읽고 상품 후보의 `image_url`에 들어갑니다. 상품 카드의 `render_product_cards` → `product_photo` → `remote_photo`가 이 URL을 서버에서 다운로드합니다.

v2.1의 `core/data/live_mcp_adapter.py:628-633`, `core/ui/product_browser.py:19`, `core/ui/product_images.py:41-58,80-84`에서 경로를 확인했습니다. 상품 이미지에 대해 URL의 IP 문자값은 검사했지만 일반 DNS 호스트가 내부 주소로 해석되는 경우는 검사하지 않았습니다. 임의 호스트와 포트도 허용했습니다.

이 문제의 공격 전제는 **외부 상품 응답의 이미지 URL을 통제하거나 상류 자료를 변조할 수 있음**입니다. 현재 앱 화면에 이미지 URL을 직접 입력하는 기능은 없습니다. 공식 서비스가 실제로 변조됐거나 인터넷의 임의 사용자가 이 앱을 직접 공격하는 데 성공했다는 의미는 아닙니다. 분류는 외부 자료가 내부 네트워크 요청으로 이어지는 조건부 SSRF 방어 누락(CWE-918)입니다.

## 안전한 재현 결과

실제 내부 주소·메타데이터 서버·외부 이미지 서버에는 연결하지 않았습니다. DNS와 HTTP 전송을 모두 모의화했습니다.

1. 기존 코드에 임의 외부 이미지 호스트를 넣고 정상 PNG 응답을 모의 제공했습니다. 요청이 차단돼야 한다는 새 검사가 실패하고 이미지가 반환됐습니다.
2. 읽기 전용으로 불러온 v2.1 코드에 허용 사이트 모양의 호스트가 `127.0.0.1`로 해석되는 상황을 모의 제공했습니다. 원본은 모의 전송 1회 후 이미지를 반환했습니다.
3. 같은 DNS 응답을 수정본에 제공하면 연결 객체 생성이 0회이며 사진 없음으로 처리됐습니다.

이 재현의 실제 HTTP 요청은 **0회**입니다. 조사 중 모의화하지 않은 내부 네트워크 연결은 없었습니다. 세부 재현 출력은 로컬 임시 검사 자료에 남겼으며 공개 앱 데이터로 재사용하지 않습니다.

## v2.1.1에서 바꾼 동작

- 검토한 **정확한 호스트**만 허용합니다. 임의 하위 도메인이나 `trusted.example.evil.example` 같은 접미사 위장은 허용하지 않습니다.
- HTTPS와 기본 443 포트만 허용합니다. 2,048자를 넘는 URL, 사용자정보가 포함된 URL, 다른 포트, HTTP, 조각 식별자, 제어문자·역슬래시는 다운로드하지 않습니다.
- DNS 결과가 비어 있거나 하나라도 비공인·내부·링크 로컬·멀티캐스트·예약 주소이면 연결하지 않습니다. IPv4와 IPv6를 함께 검사합니다.
- 검사한 **숫자 IP**로 직접 연결합니다. TLS SNI·인증서의 기대 호스트·HTTP Host는 원래 허용 호스트로 유지하고 CA 검증을 켭니다. 검사 후 원래 DNS 이름을 다시 연결 대상으로 사용하지 않습니다.
- 직접 `urllib3.HTTPSConnectionPool`을 사용해 환경 프록시, `.netrc`, 기존 세션 쿠키가 전달되지 않게 했습니다. 리디렉트와 자동 재시도는 0회입니다.
- 기존 3MiB 바이트 상한과 2,000만 픽셀 상한을 유지합니다. 선언된 크기도 먼저 검사하며 압축된 HTTP 본문은 받지 않습니다. 본문을 작은 단위로 읽고 진행 시간도 확인합니다.
- 사진을 차단하거나 받지 못하면 기존 자리 표시 그림을 사용합니다. 상품 후보·가격·장바구니·재고를 가상 자료로 바꾸지 않습니다.

검사 대상 호스트 근거는 다음과 같습니다.

| 호스트 | 현재 프로젝트에서 확인한 근거 |
| --- | --- |
| `tqklhszfkvzk6518638.edge.naverncp.com` | 보관된 CU 공식 사진 카탈로그의 실제 이미지 URL |
| `image.woodongs.com` | 보관된 GS25 실제 상품 응답의 이미지 URL |
| `cu.bgfretail.com` | 기존 CU 공식 수집기의 원본 사이트 |
| `www.7-eleven.co.kr` | 기존 세븐일레븐 공식 수집기의 원본 사이트 |
| `new.7-elevenapp.co.kr` | 공식 선택 재고/상품 메타데이터 원본 사이트 |
| `emart24.co.kr`, `www.emart24.co.kr` | 기존 공식 행사 사이트와 같은 공식 호스트 |

마지막 다섯 호스트는 현재 수집기의 공식 출처에 한해 허용한 것이며, 모두에서 실제 이미지 다운로드가 성공했다는 뜻은 아닙니다. 새 CDN 호스트가 나타나면 확인 후 코드의 정확한 허용 목록을 갱신해야 합니다.

TLS SNI와 숫자 IP 연결 방식은 [urllib3 공식 고급 사용 문서](https://urllib3.readthedocs.io/en/stable/advanced-usage.html#custom-sni-hostname)를 확인했고, 설치된 urllib3 2.8.0의 공개 생성자·요청 메서드 서명과 대조했습니다. `assert_same_host=False`는 숫자 연결 대상과 원래 호스트가 다르기 때문에 사용하며, 별도의 `assert_hostname`·`server_hostname`·CA 검증은 유지합니다.

## 검증과 남는 범위

`tests/test_security_product_images.py` 신규 **13개**와 기존 `tests/test_product_list.py` **8개**, 합계 **21개** 검사 통과(0.259초). 두 파일의 컴파일 검사도 통과했습니다.

- 임의 호스트·HTTP·비표준 포트·사용자정보·접미사 위장 차단.
- 내부·메타데이터·링크 로컬·IPv6·혼합 DNS·빈 DNS·DNS 오류 차단.
- 숫자 IP 고정, 원호스트 SNI/인증서/Host 유지, 환경 프록시·쿠키·인증정보 미전달.
- TLS 검증 실패 시 우회/재시도 없음, 리디렉트 차단.
- 선언/실제 바이트 초과·압축 본문·본문 시간 초과·잘못된 이미지의 안전한 대체 표시.
- 기존 CU 카탈로그와 관측 GS 이미지 호스트의 정상 PNG 재생, 사진 640×420 표시 및 기존 로컬 사진 기능 유지.

자동 검증은 모의 응답이며 외부 이미지 서버의 현재 가용성을 보장하지 않습니다. DNS 조회에는 운영체제의 시간 제한을 사용합니다. 연결 2초·읽기 유휴 3초와 본문 진행 예산 8초는 서로 다른 제한으로, DNS·헤더를 포함한 전체 요청이 정확히 8초 안에 끝난다는 보장은 하지 않습니다. CA 검증을 낮추거나 접근 제한을 우회하지 않았습니다. 전체 앱 회귀 검사는 최종 v2.1.1 보안 보고서를 기준으로 합니다.
