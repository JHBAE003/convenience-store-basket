# v2.1 행사 수집 점검

확인일: 2026-10-31. 로그인 없이 공개된 화면·HTML·화면이 불러오는 JavaScript만 확인했다. 인증정보나 비공개 앱 API는 사용하지 않았다.

## 기존 코드와 변경

- CU·세븐일레븐·이마트24는 기존 공식 HTML 수집기를 유지했다. GS25의 기존 수집기는 공식 API가 아니라 `편의점행사.com`의 JSON-LD 목록이었다.
- 행사 캐시는 기존 6시간을 유지한다. 같은 CU·세븐일레븐 목록을 여러 상품에서 요청하면 한 번 수집한 브랜드 목록을 재사용한다. 같은 진행 중인 목록 수집도 공유한다. GS25·이마트24는 키워드별로 구분한다.
- CU의 행사 AJAX는 신규 세션에서 선행 화면 GET 없이 정상 응답했다. 각 행사 탭 앞의 중복 GET 2회를 제거했다. 1+1·2+1 탭은 그대로 조회하고 기존 페이지 상한도 유지한다.
- 이마트24는 공개 카드 자체에 행사 종류가 있어 5개 혜택별 반복 조회를 `category_seq=0`의 키워드 조회 1회로 줄였다. `onepl`·`twopl` 등의 실제 행사 표시와 카드 기간을 읽는다.
- 원본에 연도가 없는 `10.01 ~ 10.31`은 그대로 저장한다. 확인한 연도를 붙여 ISO 날짜를 만들지 않는다. 전체 연월일이 제공되는 경우에만 날짜 필드를 채운다.
- 구매·증정 수량은 명시된 묶음에서 구조화한다. 회원 조건·카드 조건·교차증정이 명시되지 않으면 각각 `미확인`·`미확인`·미확인 상태로 남긴다.
- 행사 확인 시각(`promotion_checked_at`), 원본 기간, 출처 URL, 원문 기간을 구분한다. 원본 갱신 시각이 없으면 새로 만들지 않는다.
- 브랜드 상품 목록 가격은 점포별 현재 확정 가격이 아니므로 `REFERENCE`로 둔다. 행사 수집 성공만으로 확정 결제액이 생기지 않는다.
- 빈 결과는 행사 여부 미확인이다. 실패도 행사 없음으로 바꾸지 않는다. 실패 후 15초 대기하며 자동 재시도는 하지 않는다. 강제 재조회도 이 대기 제한을 지킨다.
- 행사 관리자 API의 명시적 `force=True`는 앱의 행사 캐시를 우회한다. 화면의 재고 재조회는 별도 행사 캐시를 유지한다. 중계나 원본이 강제로 갱신됐다고 표시하지 않는다.
- 오래된 캐시를 참고로 돌려주는 경우에도 기존 확인 시각을 유지하고 `app_cache_used=True`로 표시한다. 종료된 행사는 캐시 나이와 관계없이 한국 날짜로 다시 차단한다.

## GS25 공식 출처 조사

기존 주소 [GS25 행사상품](https://gs25.gsretail.com/gscvs/ko/products/event-goods)은 실제 요청에서 [새 GS Retail 브랜드 화면](https://www.gsretail.com/brand/gs25)으로 이동했다. HTML은 Vue 앱의 시작 화면이며 기존 상품 HTML 파서를 재사용할 수 없다.

이 화면에서 공개한 인덱스·벤더·접근성 스크립트를 확인했다. 공개 코드의 행사/이벤트 화면은 우리동네GS 앱의 행사 확인 안내였다. 상품별 월간 행사 목록을 반환하는 공개 요청 계약은 이 확인 범위에서 발견하지 못했다. 공개 점포 찾기 API가 보인다는 사실은 행사 API가 존재한다는 근거가 아니다. 비공개 앱 요청을 추정하거나 로그인 우회를 시도하지 않았다.

따라서 GS25 공식 자동 수집원을 구현했다고 주장하지 않는다. 기존 제3자 수집을 **편의점행사.com GS25 행사 목록**이라는 출처가 표시되는 보조 자료로 유지했다. 그 사이트가 제공하는 월·`priceValidUntil`은 기간으로 보존하되 미확인 회원/카드/교차증정 조건을 임의로 확정하지 않는다.

## 제한한 실제 확인

아래는 Python 요청으로 실제 수행한 범위다. 웹 읽기 도구로 공개 주소를 별도 확인했으며, 전체 페이지·전 브랜드 전체 행사 목록 수집을 실행하지 않았다. 요청 수는 `requests` 호출 단위이고 자동 리다이렉트는 별도 표기했다. 시간은 단일 관측으로, 서비스 간 속도 순위를 뜻하지 않는다.

| 대상 | 요청 범위 | 실제 결과 | 관측 시간 |
| --- | --- | --- | --- |
| CU | 공식 화면 GET 1회, 1+1 AJAX 첫 페이지 POST 1회 | 모두 HTTP 200, AJAX 카드 40개·다음 페이지 존재 확인 | 화면 0.297초, AJAX 1.638초 |
| 세븐일레븐 | 공식 1+1 AJAX 첫 페이지 POST 1회 | HTTP 200, 상품 카드 파싱 가능. 중첩 `pic_product` 중 빈 카드는 제외 | 1.824초 |
| 이마트24 | 공식 콜라·1+1 검색 GET 1회 | HTTP 200, 행사 라벨·연도 없는 기간 확인 | 0.429초 |
| 이마트24 v2.1 | 새 코드로 콜라·전체 혜택 GET 1회 | HTTP 200, 참고 상품 19행·라벨·원문 기간 파싱 | 0.465초 |
| GS25 공식 | 구주소 GET 1회(자동 이동 1회 추가), 공개 스크립트 GET 3회 | HTTP 200, JavaScript 앱·행사 안내 확인. 수집용 공개 상품 API 미확인 | 화면 0.176초, 스크립트 0.086/0.382/0.387초 |
| GS25 제3자 | 콜라 검색 POST 1회 | HTTP 200, JSON-LD의 2026년 10월·종료일 확인 | 0.152초 |

이마트24의 5회→1회와 CU의 선행 GET 2회→0회는 같은 코드 경로의 요청 수 감소다. 전체 키워드·페이지 수·외부 네트워크를 맞춘 v2 대 v2.1 속도 실험은 **미측정**이다. 위 단일 응답 시간을 개선율로 사용하지 않는다. 실제 점포 가격·재고의 완전성이나 방문 시점 재고를 검증한 것도 아니다.

## 자동 검사

`tests/test_v21_promotions.py`는 한국 시간 월말·시작일 경계, 젊은 캐시에 남은 종료 행사, 미확인 날짜/조건, 연도 추정 금지, 앱 캐시 우회와 원본 시각 미제공, 동시 목록 공유와 키워드별 결과 분리, 실패 대기, CU/이마트24 요청 감소를 확인한다. 기존 행사·장바구니 계산 테스트도 함께 실행한다. 최종 전체 검사 수는 루트 검증 문서에 기록한다.

## 남은 한계

- 공개 행사 카드만으로 점포별 현재 가격·회원/카드·교차증정 조건을 완전히 확인할 수 없다. 확인되지 않은 조건은 참고 정보로만 남긴다.
- CU·세븐일레븐은 현재 공개 계약에서 키워드별 행사 조회를 확인하지 못해 브랜드 목록 수집 후 로컬 필터링을 유지한다. 기존 페이지 상한에 도달하면 일부 확인 상태를 표시한다.
- GS25 공식 상품 행사 목록 자동 수집은 확인하지 못했다. 주소만 바꾼 가짜 공식 수집기를 추가하지 않았다.
- 이마트24의 연도 없는 카드 기간은 확정 기간으로 사용할 수 없다. 연월일·조건이 확보되기 전에는 행사 할인액을 확정하지 않는다.
