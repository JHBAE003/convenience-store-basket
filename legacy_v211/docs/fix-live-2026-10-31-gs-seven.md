# GS25·세븐일레븐 조회 복구 점검

확인일: 2026-10-31. 대상은 `기말 과제 v2.1`이며 원본 v2는 변경하지 않았습니다. 실제 외부 조회와 모의 응답 검사를 구분합니다.

## 재현한 원인과 적용

### GS25: 상품 코드만 보내면 실제 서버의 필수 상품명 검증에서 거절

통합 도구 스키마는 `itemCode`를 제공하면 상품명 검색을 건너뛴다고 설명합니다. 하지만 현재 실제 서버는 브랜드별 입력 검증 단계에서 `keyword` 문자열도 요구했습니다. 기존 v2.1은 선택 코드만 전달해 재고 요청이 SDK 검증에서 거절됐습니다.

실제 오류는 JSON 배열 안의 `invalid_type`, `path: ["keyword"]`, `Invalid input: expected string, received undefined`였습니다. 이전 MCP 클라이언트는 오류 JSON이 객체라고 가정해 이 배열을 빈 오류 상세로 바꿨습니다. 그 결과 사용자는 원인을 알 수 없는 조회 실패만 보게 됐습니다.

선택한 상품의 **코드와 상품명을 함께** 전달하도록 수정했습니다. 별도 상품 검색을 추가하지 않고 `check_inventory` 한 번으로 전달하며, 상품 코드가 있는 계약의 검색 생략을 유지합니다. REST 보조 경로에도 같은 상품명을 포함합니다. SDK 배열 오류와 JSON-RPC 오류의 원본 정보를 보존하도록 클라이언트도 수정했습니다.

수정 후 같은 GS25 상품으로 실제 재고 요청 1회가 성공해 20개 점포의 수량을 파싱했습니다. 재고 0도 정상적으로 유지했습니다. 상품 검색 응답의 `stockCheckEnabled=false` 표시만으로 재고가 불가능하다고 단정할 수 없다는 점도 확인했습니다.

### 세븐일레븐: 현재 정상 응답 확인, 일부 실패 표식과 정상 빈 결과 구분

현재 실제 `search_products`는 신라면 3개 후보와 참고 가격을 반환했습니다. 선택 상품명과 `storeKeyword=서울 중구`로 조회한 재고도 3개 점포에서 정확 수량 5·5·16을 반환했습니다. 과거의 중계 오류를 현재의 전면 장애라고 판단하지 않습니다.

서비스가 `stockAvailable=false`와 오류를 반환하는 경우에는 정상적인 빈 재고 목록과 구분하도록 보완했습니다. 정상 빈 목록이나 수량 0을 오류로 바꾸지는 않습니다. 상품의 1,000원 `salePrice`는 상품 목록 가격이므로 점포 확정 가격으로 승격하지 않습니다.

추가 읽기 검토에서 REST 보조 경로가 `storeKeyword`를 빠뜨리는 문제도 확인했습니다. 세븐일레븐 재고는 위경도가 아닌 지역 검색어 계약이므로, 보조 경로에도 주 경로와 같은 지역을 전달하도록 수정했습니다. 캐시된 행정구역을 전달한 경우 위치 서비스를 다시 호출하지 않는 모의 회귀를 추가했습니다. 이 보완 후 추가 실제 요청은 실행하지 않았으며, 후속 특정 상품·지역의 주 경로 실패 원인까지 해결됐다고 주장하지 않습니다.

### 이마트24: 재고 수량과 별도로 제공되는 점포 좌표 결합

다른 담당자가 확보한 실제 이마트24 응답을 재생해 점검했습니다. `inventory.stores`의 수량과 `nearbyStores.stores`의 좌표를 연결하지 않아, 재고가 있어도 위치가 미확인으로 남는 문제가 있었습니다.

점포 이름이나 배열 순서가 아닌 **정확히 같은 점포 코드**로만 위치를 결합했습니다. 점포 목록에만 있는 매장은 재고 행을 새로 만들지 않습니다. 같은 코드의 좌표가 서로 충돌하면 임의로 하나를 선택하지 않습니다. 상품 목록 가격은 참고 가격으로 보존하고, 원본 시각을 새로 만들지 않습니다. 기존 CU와 이마트24 응답 재생 검사도 함께 통과했습니다.

## 실제 요청 범위

좌표는 공개 기준점인 서울시청 37.5665, 126.9780이며 개인 위치를 사용하지 않았습니다. 모든 조사 클라이언트의 네트워크 재시도는 0회였습니다.

## 검증

`tests/test_fix_live_contracts.py` 신규 8개, CU/이마트 재생 2개와 기존 어댑터·재고·독립 회귀를 합한 관련 **47개 검사 통과**, 컴파일 검사 통과.

- GS25 선택 코드와 필수 상품명을 한 번의 재고 호출에 함께 전달. REST 보조 경로도 코드·상품명을 함께 전달하고 후보 검색을 반복하지 않는지 별도로 검증.
- SDK JSON 배열 오류의 원래 필드 경로·메시지 보존.
- JSON-RPC 오류의 세부 정보 보존.
- 세븐일레븐 명시적 재고 불가와 정상 빈 목록 구분.
- 점포 코드 기준 좌표 결합, 수량 0 유지, 점포 정보만 있는 행을 재고로 만들지 않음.
- 좌표 충돌을 임의로 해소하지 않음.

자동 검사는 모의 응답을 사용하며 실제 외부 성공을 대신하지 않습니다. 최종 전체 검사와 화면은 Root의 최종 검증 기록을 기준으로 합니다.

## 남은 범위

- GS25 수정 후 파싱된 재고에는 가격이 0(미확인)이며 원본 재고 시각은 제공되지 않았습니다. 없던 가격이나 원본 시각을 만들어 확정 추천으로 올리지 않습니다.
- 세븐일레븐 상품 가격은 점포 현재 결제액이 아닌 참고 가격입니다. 행사·점포 가격 검증은 별도입니다.
- 세븐일레븐의 원본 `distanceM=0`은 사용자 기준 거리를 보장하지 않습니다. 화면의 거리 비교는 사용자 좌표와 반환된 점포 위경도로 계산해야 합니다. 기존 장바구니 계산은 이를 재계산합니다.
- 이번 단일 시점의 성공은 모든 상품·모든 위치·향후 서비스 정상 동작을 보장하지 않습니다. v2 대비 속도 개선율은 측정하지 않았습니다.

## 후속 특정 상품·지역 오류와 독립 직접 경로 조사

Root의 실제 서울대 인근 펩시 조회에서는 다른 세 브랜드가 수량을 반환했지만, 세븐일레븐 주·보조 경로가 모두 HTTP 502를 반환했습니다. 주 경로 오류 코드는 `CONVENIENCE_RELAY_FAILED`, 진단은 일시적인 외부 오류였습니다. 이 특정 실패를 상품명 SDK 누락이라고 해석하지 않았습니다. 앞의 서울 중구 신라면 성공과 함께 기록해야 합니다.

현재 공개 저장소의 `src/services/seveneleven/api.ts`, `client.ts`, `inventory.ts`, `transport.ts`와 복구 문서를 읽어, 같은 중계에 의존하지 않는 직접 경로가 코드에 존재하는지 조사했습니다. 브랜드 자료 요청은 추가하지 않았습니다.

- 공식 앱 공개 도메인 `new.7-elevenapp.co.kr`의 상품 재고 메타데이터 GET, 지역 매장 검색 POST, 점포별 수량 POST를 이용하는 직접 코드가 있습니다.
- 재고 메타데이터는 선택한 내부 상품 코드로 조회하며, 수량 요청은 메타데이터의 재고관리 필드와 점포 코드 1개를 사용합니다. 여러 점포를 한 번에 넣으면 원본이 거절한다는 공개 복구 기록이 있습니다.
- 현재 직접 코드의 기본 헤더에는 명시적 로그인 토큰·Authorization·signEnc가 없습니다. 따라서 이 코드 확인만으로 로그인 필수 또는 인증 때문에 불가능하다고 단정할 수 없습니다.
- 선택적인 유료 수집 대행 fallback도 있지만 이 프로젝트에 도입하지 않았습니다.
- 공개 복구 문서는 직접 요청의 접근 거절·HTML 응답·중계 502가 실행 환경과 시간에 따라 달라진 사례를 기록합니다. 특정 실행 환경 변경이나 직접 연결이 지속적인 복구를 보장하지는 않습니다.
- 이 PC에서 그 직접 요청의 현재 정상 여부는 별도 브랜드 자료 요청 없이 확인할 수 없으므로 **미검증**입니다. 검증되지 않은 직접 어댑터를 추가해 정상이라고 표시하지 않았습니다. 인증 우회·쿠키 추출·유료 API·공개되지 않은 키는 사용하지 않았습니다.

## 독립 공식 직접 경로의 실제 확인 결과

이후 Root가 공개 읽기 요청 3회로 제한해 직접 경로를 확인하도록 허용했습니다. 같은 펩시600ml 내부 코드와 서울대 기본 좌표를 사용했습니다. SSL 검증은 기본값으로 유지했고, 자동 재시도·리다이렉트 추적·로그인·인증정보·유료 수집 대행·차단 우회를 사용하지 않았습니다.

| 단계 | 실제 요청 | HTTP 시도 수 | 관측 결과 |
| --- | --- | ---: | --- |
| 선택 코드 메타데이터 | 공식 상품 재고 메타데이터 GET | 1 | HTTP 200, 191ms. 정확한 코드와 상품명, 참고가 2,500원, 재고관리 필드 제공 |
| 지역 점포 | 관악구 점포 검색 POST | 1 | HTTP 200, 154ms. 점포 32개와 원본 위경도 제공 |
| 단일 점포 수량 | 가장 가까운 서울대학생회관점 55457 수량 POST | 1 | HTTP 200, 380ms. 재고 20개, 사용자 기준 직선거리 약 0.169km |

직접 자료 요청 총 **3회**가 모두 정상 JSON을 반환했습니다. 현재 이 PC와 해당 상품·지역에서는 중계 502와 별도로 공식 직접 조회가 가능하다는 증거입니다. 전 점포·다른 상품·향후 접근을 보장하지 않으며, 직접 경로의 구현·통합 여부는 최종 변경 내용을 확인해야 합니다. 원본 재고 시각은 여전히 미제공이며, 2,500원은 점포 결제액이 아닌 공식 상품 참고 가격입니다.

원자료: [공식 직접 조회 3회 기록](research/fix-seven-direct-probes.json). 단계별 응답을 다음 단계에 사용했으며, 점포 목록에서 가장 가까운 실제 점포 코드를 선택해 단일 점포만 요청했습니다. 과거 자료를 새 LIVE 응답으로 대체하지 않았습니다.


## 공식 직접 보조 구현 결과

실제 3단계 성공을 확인한 뒤 기존 `CompositeInventoryAdapter`의 세븐일레븐 선택 상품 보조 경로를 공식 직접 경로로 교체했습니다. 주 MCP 경로가 정상인 경우에는 이 보조를 실행하지 않는 정책을 유지합니다. 새 범용 클라이언트·인증·유료 API를 도입하지 않았습니다.

- 선택 내부 코드로 공식 상품 메타데이터를 받고, 응답 코드가 다르면 점포·수량 요청 전에 중단합니다.
- 지역 점포 목록은 `selected_stores` 원문 목록으로 보관합니다. 세션별 원천 구분 캐시가 목록을 주입하면 재사용하며 점포 목록 HTTP를 다시 요청하지 않습니다.
- 받은 지역 목록에서 사용자 좌표 기준 직선거리를 계산해 가까운 최대 3개 점포만 순서대로 요청합니다. 수량 요청의 점포 코드는 매번 하나입니다.
- 목록이 더 크면 `catalog_incomplete=True`와 한국어 확인 범위를 남깁니다. 부분 확인을 전체 지역 성공으로 표시하지 않습니다.
- 공식 HTTP는 메타데이터 1회 + 점포 목록 최대 1회 + 수량 최대 3회로, 한 보조 실행당 최대 5회입니다. 이 경로 자체의 자동 재시도는 없습니다. 캐시한 점포 목록이 있으면 최대 4회입니다.
- 재고 0은 확인된 0으로 보존합니다. 음수·누락·충돌·개별 점포 실패는 수량 미확인으로 남기며 다른 점포의 성공은 유지합니다.
- 선택한 모든 점포가 실패하면 메타데이터·점포 목록·오류·원본 응답을 보존한 `LiveDataError`로 전체 재고 실패를 알립니다. 메타데이터 성공만으로 재고 성공이라고 표시하지 않습니다.
- 접근 거절·인증 요구·호출 제한이면 남은 점포 요청을 중단합니다. SSL 검증을 낮추거나 쿠키·인증값·프록시로 우회하지 않습니다. HTML을 재고로 읽지 않습니다.
- 상품의 2,500원은 `REFERENCE`, 행사 조건은 미확인, 원본 재고 시각은 빈 값으로 유지합니다. 앱 수신 시각은 별도입니다.

`tests/test_seven_direct_recovery.py` 신규 10개와 기존 계약·응답 재생·어댑터·독립 회귀를 합한 **관련 57개 검사 통과** 및 컴파일 검사 통과. 실제 세 단계 응답을 모의 재생했으며, 최근접 순서·3개 상한·점포 목록 재사용·코드 불일치 중단·정상 0·부분 실패·전체 실패·403 즉시 중단·누락/음수/충돌을 확인했습니다. 이 구현 후 이 담당자는 추가 실제 브랜드 요청을 하지 않았습니다. Root의 최종 UI 보조 실행은 별도 기록을 따릅니다.

기존 REST 보조의 지역 조건 누락 보완은 조사 과정의 중간 수정입니다. 최종 세븐일레븐 선택 보조는 위의 공식 직접 경로를 사용합니다. GS25 REST 보조는 상품명과 선택 코드를 함께 전달하는 수정 그대로 유지합니다.
