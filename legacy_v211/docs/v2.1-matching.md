# v2.1 상품 연결과 선택 대체품 조회

## 상품 식별 기준

- 공통 바코드와 브랜드 내부 상품 코드를 별도 필드로 비교합니다. 두 필드에 우연히 같은 문자열이 들어 있어도 서로 같은 식별자라고 판단하지 않습니다.
- 명시적 바코드가 양쪽에 있으면 우선 비교합니다. 유효한 GTIN의 선행 0 차이는 정규화합니다. GTIN 체크 숫자가 맞지 않는 값은 브랜드 간 공통 바코드 자동 연결에 사용하지 않습니다. 기존 시연용 `DEMO-*` 식별자는 같은 필드 안에서 유지합니다.
- 같은 브랜드의 내부 상품 코드는 해당 브랜드 안에서만 비교합니다. 상품·행사 통합은 브랜드가 다른 자료를 섞지 않습니다.
- 식별자를 직접 비교할 수 없으면 제조사·전체 상품명·용량·맛·포장 수량의 지문을 비교합니다. 제조사나 용량을 확인하지 못한 이름만으로는 자동 연결하지 않습니다. `500ml`와 `0.5L`처럼 명확한 단위 차이는 정규화하되, g와 ml를 환산하지 않습니다.
- 식별자가 같아도 원본이 명시한 제조사·용량·맛·포장 수가 충돌하면 연결하지 않습니다. 상품명과 별도 규격 필드가 서로 충돌하는 응답도 보류합니다.
- 이름에 적힌 맛 표현은 차이를 거절하는 보조 정보로 사용합니다. AI 분류나 이름 유사도 점수로 같은 상품이라고 확정하지 않습니다. 해석하지 못한 구성 기호는 상품 지문에 남깁니다.

사진 목록의 상품명과 참고 판매가는 매장 관측으로 승격하지 않습니다. 사진 재사용도 같은 브랜드와 안전한 상품 연결 근거를 요구합니다.

## 사용자가 확인한 연결 재사용

기존 `CatalogLink` 구조와 `sample_data/catalog_links.csv`를 유지합니다. 선택 규격 필드를 추가해도 기존 5열 시연 연결표를 그대로 읽을 수 있습니다. 사용자가 확인한 실제 상품 연결은 새 폴더의 `user_data/confirmed_links.csv`에 별도로 저장합니다. 이 파일은 같은 컴퓨터에서 재사용하는 로컬 연결표입니다.

저장에는 명시적 확인과 브랜드별 상품 코드가 필요합니다. 같은 상품이 서로 다른 과거 연결 그룹에 중복되어 그룹 구성까지 충돌하면 임의로 하나를 선택하지 않습니다. 잘못된 CSV를 읽었을 때 오류를 표시하고 기존 파일을 덮어쓰지 않습니다. 쓰기는 임시 파일에 기록한 뒤 교체하며, 같은 앱 프로세스의 동시 저장을 보호합니다.

## LIVE 대체품 조회 순서

1. **대체 상품 조회**로 상품 목록만 가져옵니다. 목록에 점포 좌표가 없어도 후보를 표시합니다.
2. 사용자가 대체 후보 하나를 선택하고 원상품·대체품의 종류와 용량을 확인합니다.
3. **선택 대체품 재고 확인**을 눌렀을 때만 선택한 코드로 재고를 조회합니다. 상품 목록의 참고 가격은 대체 구매액에 사용하지 않습니다.
4. 재고가 반환된 뒤 반경을 적용하고, 가격·행사·재고의 근거와 수량을 검사합니다. 해당 브랜드의 성공 범위가 없거나 일부 실패·저장 자료로 분류되면 확정 대체안에 사용하지 않습니다.
5. **이 상품으로 교체**를 눌러야 장바구니를 변경합니다. 후보·용량·위치·브랜드·허용 조건을 바꾸면 이전 확인 결과를 적용하지 않습니다.

반환된 원상품·상품 별칭 관측도 검사 자료에서 숨기지 않습니다. 같은 시각의 상충 가격이나 재고가 있으면 제안을 보류합니다. 조회 오류 뒤에는 화면이 다시 그려졌다는 이유만으로 요청하지 않으며 사용자의 다음 확인 클릭을 기다립니다. 시연 모드는 기존 CSV 흐름을 유지합니다.

## 검증 범위

- `tests/test_v21_matching.py`: 23개 검사. 식별자 공간 분리, GTIN 패딩·체크 숫자, 서로 다른 용량·맛·포장, 원본 자체의 규격 충돌, 보수적인 이름 연결, 기존 CSV, 저장·재사용·충돌 그룹·동시 쓰기·손상 파일 보존을 확인했습니다.
- `tests/test_v21_substitute_ui.py`: 6개 AppTest. 상품 목록 검색 시 재고 미조회, 선택 코드만 명시적 재고 조회, 목록 참고가 미사용, 승인·조건 변경, 오류·품절·시각 미제공·범위 밖·일부 성공·저장 자료·잘못된 TEST 응답, 원상품 별칭 충돌, 실제 적용 버튼을 확인했습니다.
- 기존 `tests/test_v2_app.py`, `tests/test_v2_regressions.py`: 13개 검사 통과. 새 LIVE 호출 순서와 명시적 행사 조건에 맞게 모의 자료를 보완하면서 기존 시연·승인 초기화·별칭 충돌·만료 거절의 검사 의도를 유지했습니다.

위 검사는 모의 자료를 이용한 자동 검사입니다. 이 문서의 결과를 실제 외부 재고 서비스 성공이나 속도 측정으로 해석하면 안 됩니다. 실제 연결 확인과 전체 검사 결과는 별도 검증 기록을 참고하세요.
