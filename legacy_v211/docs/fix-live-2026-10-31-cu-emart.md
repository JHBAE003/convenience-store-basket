# CU·이마트24 실조회 불량 진단

확인일: 2026-10-31. 기본 위치인 서울대학교 인근 `37.458115, 126.952161`에서 재고·상품 자료 요청을 브랜드별 2회씩 수행했다. 네트워크 재시도는 0회, 요청 제한 시간은 15초였다. 이 문서의 실제 요청은 CU 2회·이마트24 2회, 합계 4회다. 공개 문서·위치 검색·REST·공식 보조 API의 추가 원격 요청은 수행하지 않았다. 이후 검증은 저장한 응답과 모의 응답으로 진행했다.

## 실제 응답

| 브랜드·단계 | 공개 통합 도구와 조건 | HTTP 시도 | 단일 응답 시간 | 관측 결과 |
| --- | --- | ---: | ---: | --- |
| CU 후보 | `check_inventory`, 검색어 `펩시`, size 5, offset 0, storeLimit 3 | 1 | 2,467ms | 정상. 상품 전체 22개 중 5개 반환, 첫 후보 재고 3점포 반환 |
| CU 사진 상품 | `check_inventory`, 정확명 `롯데)펩시콜라P600ml`, size 5, offset 0, storeLimit 5 | 1 | 2,315ms | 정상. 해당 상품 1개와 6점포 중 5점포 반환 |
| 이마트24 후보 | `search_products`, 검색어 `펩시`, page 1, pageSize 3 | 1 | 1,276ms | 정상. `standard.products`와 브랜드 상품 코드·참고 가격 반환 |
| 이마트24 선택 재고 | `check_inventory`, pluCd `8801056175955`, 서울특별시·관악구, storeLimit 5 | 1 | 2,080ms | 정상. `inventory.stores` 4개에 수량 반환, `nearbyStores.stores` 5개에 좌표 반환 |

각 단계 한 번씩의 관측으로 평균이나 개선율을 측정한 것은 아니다. 이 문서의 결과를 모든 품목·지역·시간의 정상 동작 보장으로 해석하지 않는다.

## CU에서 확인한 사실

사진 목록의 `롯데)펩시콜라P600ml`에 저장된 코드 `8801056193010`은 현재 중계 응답의 `inventory.items[].itemCode`와 일치했다. 사진 코드가 해당 상품 조회를 막는 문제는 이 사례에서 재현되지 않았다.

정확명 조회의 `nearbyStores.stockItemCode`도 같은 코드였고 `selectionReason`은 `exact_match`였다. 실제 응답의 예시는 다음과 같다.

- 서울대200동점: 재고 13개, 원본이 제공한 거리 317m.
- 서울대학교신양점: 재고 16개, 원본이 제공한 거리 530m.
- 상품 후보 목록 가격: 2,500원. 점포별 가격 필드는 제공되지 않았으므로 현재 점포의 확정 판매가가 아닌 참고가다.
- `received_at`은 앱이 응답을 받은 시각으로 기록할 수 있다. 원본 재고 시각은 제공되지 않았으므로 `source_updated_at`, `stock_updated_at`은 빈 값으로 유지한다.

따라서 이 사례는 **재고 응답 실패가 아니라, 정상 반환 수량이 확정 추천 기준 때문에 미확인으로 처리되는 상태**다. 응답 수량을 사용자에게 보여주는 일과 방문 시점 재고를 확정하거나 추천 계산에 쓰는 일을 구분해야 한다.

## 이마트24에서 확인한 원인

실제 선택 재고 응답은 다음 구조였다.

```text
inventory.goodsInfo.viewPrice = 2500
inventory.goodsInfo.pluCd = 8801056175955
inventory.stores[] = { bizNo, bizQty, storeName, address, distanceM }
nearbyStores.stores[] = { storeCode, latitude, longitude, address, distanceM, ... }
```

현재 `check_selected`를 동일 응답으로 재생하면 참고 가격 2,500원과 재고 21·17·19·16개는 정상 보존했다. **확인된 파서 문제는 재고 행과 매장 목록을 점포 코드로 합치지 않아 위도·경도가 모두 미확인으로 남는 점**이다. 재고 4개 점포의 `bizNo`가 매장 목록의 `storeCode`에 모두 존재하므로 추정 없이 정확히 합칠 수 있다.

이 경우 가격을 0으로 잃는다고 단정해서는 안 된다. `goodsInfo`를 생략하고 내부 일반 파서만 직접 호출하면 0이 되지만, 실제 `check_selected`는 `goodsInfo`를 상품 메타데이터로 넘겨 이미 `REFERENCE` 가격으로 보존한다. 실제 호출 경로 재생으로 이를 구분해 확인했다.

또한 반환된 4개 점포의 거리는 2.305~2.682km였다. 기존 앱의 최대 반경 2km에서는 정상 응답이어도 반경 안의 점포가 없다. 반경 밖 결과를 조회 실패로 표현하면 안 되며, 반경 확대나 제외 점포 수 안내가 필요하다. 원본 재고 시각과 점포별 확정 판매가는 이 응답에서도 제공되지 않았다.

## 브랜드 전체 조회의 표시 문제

기본 사진 목록 12개는 모두 CU 상품이다. 사진 하나를 담았다고 다른 브랜드의 상품 코드가 저절로 확인되는 것은 아니다. 다른 브랜드에 확인한 연결이 없으면 **미연결**로 안내해야 하며, 외부 서비스 **조회 실패**와 구분해야 한다. 비슷한 이름으로 다른 브랜드의 용량·맛·포장 상품을 임의 연결해서는 안 된다.

## 재현 검사와 적용 확인

`tests/test_fix_cu_emart_replay.py`는 실제 공개 응답의 구조만 재현한 모의 자료를 사용한다. 외부 요청을 하지 않는다.

- CU: 사진 코드와 응답 코드 일치, 정상 수량 13개, 2,500원 참고가, 원본 시각 미제공 유지.
- 이마트24: 재고·매장 코드의 정확한 결합, 위도·경도 복원, 정상 수량 0 유지, 매장 목록에만 있고 수량이 없는 점포를 임의 재고 0으로 추가하지 않음, 참고가·원본 시각 미제공 유지.

첫 재현 실행에서는 CU 검사가 통과했고 이마트24 좌표 결합 검사는 `(None, None)`으로 실패했다. 이 재현은 어댑터 담당자에게 전달했다. 최종 수정 후 재검사 결과: **2개 모두 통과**. 추가 외부 요청 없이 저장한 실제 이마트24 응답도 다시 재생해 4개 재고 점포 모두 정확한 점포 코드로 위도·경도가 결합됨을 확인했다. 수량 21·17·19·16개, 참고가 2,500원, 원본 재고 시각 미제공 상태는 그대로 유지됐다.

실시간 조회 실패를 시연 자료로 대체하거나 원본 시각을 새로 만들지 않았다. CU·이마트24가 반환한 수량과 참고 가격을 확인했어도 현재 매장의 최종 결제액을 확정할 근거가 생긴 것은 아니다.
